# Памятка ОП: одна компания — одна карточка

Расчёт премии определяет тип клиента по числу его сделок, а клиента опознаёт по **ИНН
контрагента** в заказе. Новая карточка на повторный заказ + незаполненный ИНН = связи со
старыми сделками нет, клиент считается первичным, премия за постоянного не начисляется.

Веб-версия памятки для ОП: артефакт «Одна компания — одна карточка» (август 2026).

## Состояние базы на 2026-08-24

- 1433 карточки клиентов заведены на 596 реальных юрлиц
- 62% корпоративных заказов 2026 года (1417 из 2293) — без ИНН контрагента
- 125 новых карточек-дублей заведено за 2026 год

## Правила

1. **Заполнять ИНН в реквизитах контрагента** — единственный надёжный признак компании.
   Название, телефон и адрес пишут по-разному, по ним связь не строится.
2. **Искать клиента по ИНН до создания новой карточки.** Поиск по названию обманчив:
   «ООО НПП "АММА"» и полное наименование из устава — одна компания, но найти её по первому
   написанию не выйдет.
3. **При смене юрлица добавлять компанию в существующую карточку.** АО «Химреактивснаб» →
   ООО «ХРС-Снабжение»: пять заказов на карточке 17959, последний — на новой 73995.
4. **Найденные дубли объединять** штатным объединением клиентов. Перестать пользоваться лишней
   карточкой недостаточно — старые заказы остаются на ней.
5. **Держать наименование единообразным** — иначе менеджер сам не найдёт существующую карточку.

## Проверка перед сохранением заказа

ИНН заполнен → по этому ИНН нет второй карточки → заказ на той же карточке, что прошлые заказы
компании → наименование как в прошлый раз.

## Связь с расчётом

Пока карточки ведутся неаккуратно, историю подстраховывает склейка `salary_client_canon`
(см. «Кто считается одним клиентом» в [OVERVIEW.md](OVERVIEW.md)). Склейка чинит прошлое —
навести порядок в новых заказах она не может: у заказа без ИНН склеивать нечего.
