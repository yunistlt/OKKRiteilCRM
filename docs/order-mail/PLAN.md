# План работ: раздел «Переписка» в карточке заказа

Постановка — `docs/order-mail/TZ.md`. Здесь только порядок работ и принятые по дороге
инженерные решения. As-built будет в `OVERVIEW.md`, когда этап 1 доживёт до прода.

## Главное инженерное решение: новых копий писем не заводим

ТЗ (§2) описывает три таблицы: треды, письма, вложения. Проверка по
`information_schema` показала, что письма уже лежат в своих канонических таблицах:

- `incoming_emails` — входящие (автоприём Катерины): есть `message_id`, `in_reply_to`,
  `email_refs`, `attachments_meta`, `imap_uid`;
- `order_email_sends` — исходящие из карточки заказа: есть `message_id`;
- `outgoing_emails` — папка «Отправленные» ящика.

Заводить четвёртую таблицу с теми же письмами — значит получить второго писателя и
расхождение (закон «проверь, что такого ещё нет»; грабля `orders.client_id`). Поэтому:

- **тред — вычисляемая величина**, а не хранимая запись. Собирается из писем по
  `References` / `In-Reply-To`, фолбэк — нормализованная тема;
- **хранимого в новых таблицах — только то, чего нигде нет**: прочитанность письма
  менеджером и состояние треда.

Если сборка тредов на лету станет дорогой, кешируем результат; переносить сами письма
не будем.

## Этап 1 — «Читаем и показываем» (в работе)

1. `migrations/20261008_order_mail_state.sql` — две таблицы:
   `order_mail_reads` (кто и когда прочитал письмо) и `order_mail_threads`
   (состояние треда: ждём нас / ждём клиента / закрыт).
2. `lib/order-mail/thread.ts` — сборка тредов из писем заказа, определение состояния,
   поиск начала цитаты (`quote_offset`). Закрыто юнит-тестами на сохранённых письмах:
   IMAP локально не работает (DPI), отладка на проде недопустима.
3. `GET /api/orders/<номер>/mail` — треды письмами, непрочитанные, состояние.
   `POST` — отметить прочитанным, закрыть тред.
4. Вкладка «Переписка» в карточке заказа: список тредов слева, тред справа, цитата
   свёрнута, вложения строкой, непрочитанные выделены, счётчик на вкладке.
5. `RouteRule` для страницы и для `/api` отдельными строками (грабля расхождения).

## Этап 2 — «Отвечаем из ОКК»

Композер в треде (не модалкой), черновик с автосохранением, отмена отправки 5–10 секунд,
отложенная отправка, шаблоны из БД, подпись из справочника. Часть уже есть в
`OrderReplyForm` — переносим, а не пишем заново.

## Этап 3 — привязка по `In-Reply-To` в автоприёме

Сейчас входящее цепляется к заказу тегом в теме и адресом. `In-Reply-To` — надёжнее
всего и его нет (ТЗ §3.1). Делаем после того, как треды научатся показывать результат:
иначе улучшение привязки невидимо.

## Этапы 4–5

Личная лента менеджера и экран «Разбор» для РОПа; отключение людям доступа к ящику.
По ТЗ §9 — после месяца жизни этапов 1–3.
