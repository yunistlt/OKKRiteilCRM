# 57 писем ушли клиентам, но их нет в «Отправленных» ящика

Разбор 25.10.2026. Отдельная задача: разобраться глубже и решить, что делать.

## В двух словах

Письмо из карточки заказа уходит клиенту напрямую по SMTP — **в почтовый ящик
`rop@zmktlt.ru` оно при этом не попадает**. Чтобы письмо было видно и в самой
почте, система отдельной задачей дописывает его копию в папку «Отправленные»
(IMAP APPEND). 12–13 октября ящик 53 раза отказался принять копию.

Итог: **57 писем октября клиент получил, а в почте их не видно.** В самой ОКК
переписка на месте — пропажа только в веб-почте и в почтовых программах.

## Цифры

| | |
|---|---|
| Писем из карточек заказа за октябрь | 727 |
| Из них копия легла в «Отправленные» | 670 |
| **Без копии** | **57** |
| Задач на дозапись всего | 624 (571 успешных, 53 мёртвых) |
| Период отказов | 12.10 с 11:00 по 18:00, 13.10 с 05:00 по 08:00 |

По дням видно, что это был сбой, а не постоянная поломка:

| Дата | Отправлено | Копия в ящике |
|---|---|---|
| 12.10 | 59 | 14 |
| 13.10 | 33 | 27 |
| 14.10 | 49 | 49 |
| 15.10 | 39 | 39 |

С 14 октября и по сей день — копии ложатся все.

## Что именно ответил ящик

| Ошибка | Раз |
|---|---|
| `Ящик не принял копию: Command failed` | 50 |
| `Ящик не принял копию: Unexpected close` | 2 |
| `Ящик не принял копию: sent_folder_not_found` | 1 |

Каждая задача честно пробовала **5 раз** и только потом ложилась в мёртвые.
`Command failed` — ответ сервера Яндекса на саму команду добавления письма;
`Unexpected close` — соединение оборвалось; `sent_folder_not_found` — папка
«Отправленные» не нашлась (единственный раз).

## Где это в коде

| Что | Где |
|---|---|
| Отправка письма (SMTP + постановка задачи на копию) | `lib/orders/deliver-letter.ts`, `lib/email.ts` → `sendOrderEmail` |
| Дозапись копии в ящик | `lib/email/imap.ts` → `appendToSentFolder`, поиск папки — `resolveSentFolder` |
| Воркер | `app/api/cron/system-jobs/email-sent-append/route.ts`, крон раз в 10 минут |
| Тело письма до дозаписи | хранилище, путь в задаче: `outgoing-mime/<messageId>.eml` |
| Сторож | уведомление `mail.sent_copy_missing` — если копии нет больше часа |

Пример задачи:

```json
{"path": "outgoing-mime/9a11a655-…@zmktlt.ru.eml",
 "subject": "[#3/54732] Re: Коммерческое предложение",
 "messageId": "<9a11a655-…@zmktlt.ru>"}
```

Тело письма сохранено в хранилище — **дозаписать копии задним числом
технически возможно**.

## Что надо выяснить

1. **Почему Яндекс отказал именно 12–13 октября.** Массовость (50 из 53 — одна
   и та же ошибка, подряд в течение дня) намекает на ограничение со стороны
   ящика: лимит одновременных сессий IMAP, лимит команд, временная блокировка.
   Проверить: сколько параллельных подключений к ящику держит система — его
   дёргают и автоприём почты, и дозапись копий, и скачивание вложений.
2. **Почему сторож молчал.** Есть уведомление «копия не легла больше часа»
   (`mail.sent_copy_missing`), но о 53 отказах никто не узнал. Проверить,
   работает ли оно и куда шлёт.
3. **Почему пять попыток подряд, а не с нарастающей паузой.** Если ящик ввёл
   ограничение, пять быстрых повторов его только продлевают.
4. **Решить, дозаписывать ли 57 копий задним числом.** Письма у клиентов, тела
   сохранены. Риск: если часть всё же легла другим путём — получится дубль в
   «Отправленных». Проверять надо по `message_id` в `outgoing_emails`.

## Как проверить текущее состояние

```sql
-- письма из карточек без копии в ящике
select s.created_at, s.order_number, s.subject
from order_email_sends s
left join outgoing_emails o on o.message_id = s.message_id
where o.message_id is null and s.created_at >= '2026-10-01'
order by s.created_at;
```

Фон: правило «отправка только через `sendOrderEmail`» и устройство переписки —
`docs/order-mail/OVERVIEW.md`.
