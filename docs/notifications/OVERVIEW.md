# Уведомления: типы сообщений и адресаты (as-built)

Читать первым при любой правке того, куда уходят сообщения в Telegram.

## Зачем это появилось

Адресат был зашит в место отправки. Каждый отправитель (оплаты, бот-РОП, аудит
системы, звонки) сам решал, в какой чат писать, и правка одного уводила другое:
28.09.2026 вместе с правкой маршрутизации платежей все оплаты ЗМКТЛ уехали из
общего чата отдела в личку владельцу, а заметили это по тишине в чате.

Теперь адресат — **свойство типа сообщения**, а не места в коде.

## Устройство

| Файл | Что в нём |
|---|---|
| `lib/notify/catalog.ts` | Каталог типов: код, русское название, описание, бот, адресат по умолчанию |
| `lib/notify/route.ts` | Разрешение адресата: тип → chat_id (учитывает переопределения из БД) |
| `lib/notify/send.ts` | Единственная точка отправки: `sendNotification(code, text, ctx)` |
| `notification_routes` | Переопределения человеком. Пустая таблица = дефолты каталога |
| `/settings/notifications` | Экран: тип сообщения → адресат, тумблер «шлём» |

Адреса чатов остались там, где жили: `sales_rop_settings.telegram_chat_id`
(общий чат отдела), `sales_rop_settings.owner_chat_id` (личка владельца),
`sales_rop_manager.telegram_chat_id` (личка менеджера), env для проектных чатов.
Второго справочника chat_id не заводим.

## Правила адресации (заданы владельцем)

- **Оплаты** — в общий чат отдела. Кроме «оплата не проведена в CRM»: это сбой,
  он уходит владельцу.
- **Ошибки системы** (аудит конвейера, сторож транскрибации, баланс ИИ, аварии
  кронов, упавший прогон бота-РОПа) — владельцу в личку.
- **Нарушение регламентов продаж, SLA, пропущенные звонки** — в общий чат.
- **Сводный план дня и итог дня по отделу** — в общий чат.
- **Подробный план дня и личный разбор звонков** — менеджеру в личку.
- **Оплаты чужих проектов** (столярка, консалтинг) — в чаты своих проектов.
- **Ведомость зарплаты** — получателям из настроек бухгалтерии.

## Что нельзя переопределить

Типы с `targetFixed` (личный план, личный разбор, оплаты чужих проектов,
ведомость) адресата в интерфейсе не меняют: подменить адресата личного
сообщения — значит разослать чужое личное. API такой запрос отклоняет.

## Как добавить новый тип

1. Строка в `NOTIFY_TYPES` (`lib/notify/catalog.ts`) — код, название по-русски,
   описание, бот, адресат по умолчанию.
2. В месте отправки — `sendNotification('<код>', текст)`. Никаких `chat_id`
   и `fetch` к api.telegram.org в бизнес-коде.
3. Тип сразу появится на `/settings/notifications`.

## Грабли

- **Нет адреса — молчим.** `sendNotification` возвращает `skipped: 'no_chat'`,
  а не падает: так было и раньше при пустом env. Проверять тишину — по логам.
- **Топик форума** (`message_thread_id`) есть только у общего чата. В личку его
  слать нельзя — Telegram вернёт ошибку.
- **Личный чат появляется, только когда человек сам написал боту.** Пока его нет,
  план дня уходит в общий чат (`fallbackToGroup`) — человек не должен остаться
  без работы из-за того, что не написал боту. На личный разбор звонков это
  правило не распространяется.
