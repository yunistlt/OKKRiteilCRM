# Режим тестировщика и проверка вёрстки по голдам (as-built)

Читать первым в новом чате, до кода.

## Что это

Автоматическая проверка всех экранов приложения на соответствие
`golds/GOLD_DESIGN_UX.md`: окна не «съедаются» другими слоями, ничего не
вылезает за край, прокрутки не вложены, углы 0px, тени/анимации, коды вместо
русских названий.

Два способа запуска — один и тот же код проверок:

| Способ | Где | Для кого |
| --- | --- | --- |
| **Режим тестировщика** в приложении | `/settings/qa` → «Включить режим», либо `?qa=1` к любому адресу | Андрей/тестировщик — кликает по экранам, видит замечания на месте |
| **Полный прогон** | `npm run ui:audit` | разработчик — все экраны × 4 окна, скриншоты, HTML-отчёт |

## Файлы

- `lib/ui-audit/screens.ts` — **реестр экранов**: маршрут, название, раздел, шаги для открытия вложенных окон (карточка заказа), публичные/пропущенные. Тест `tests/ui-audit-screens.test.ts` требует запись на каждый `app/**/page.tsx`.
- `lib/ui-audit/checks.ts` — `runUiChecks()`: самодостаточная функция, работает в браузере на живом DOM. Правила и русские тексты — тут.
- `components/qa/QaOverlay.tsx` — плавающая панель режима тестировщика (монтируется в `app/layout.tsx` при наличии сессии).
- `app/settings/qa/` — страница-хаб: список экранов, описание правил, тумблер режима. RBAC: admin.
- `scripts/ui-audit.ts` — Playwright-прогон. Сам поднимает `next dev`, выпускает локальную сессию admin (JWT ключом по умолчанию — только когда `JWT_SECRET` не задан). Отчёт в `ui-audit-report/` (в .gitignore).

## Правила (коды в `UiCheckCode`)

| Код | Серьёзность | Смысл |
| --- | --- | --- |
| `page-h-overflow` | ошибка | страница шире окна |
| `clipped` | ошибка | кнопка/поле/таблица за краем окна без прокрутки |
| `covered` | ошибка | окно/кнопка перекрыты другим слоем (`elementFromPoint`) |
| `scroll-dead` | ошибка | `overflow:hidden` обрезает контент, прокрутки нет |
| `code-in-ui` | ошибка | слаг вида `legal-entity` в тексте или в поле |
| `nested-scroll` | замечание | прокрутка внутри прокрутки |
| `radius` / `shadow` / `transition` | замечание | отступления от плоского стиля |
| `number-input` | замечание | `input[type=number]` вместо `NumberInput` |
| `touch-target` | замечание | <36px на телефоне |

## Разметка-подсказки в DOM

- `data-ui-audit="order-row" / "order-modal"` — якоря для шагов реестра.
- `data-ui-audit-zone="sidebar|header|consultant|phone"` — зоны оболочки. В отчёте их находки сводятся один раз на всё приложение, а не на каждый экран; в панели скрыты за галкой «оболочка».
- `data-ui-exception="whatsapp"` — чат Семёна, разрешены скругления/тени (голд §5.6).
- Точечные исключения: `data-ui-audit-round="ok"`, `-shadow="ok"`, `-motion="ok"`, `-number="ok"`, `-code="ok"`, `-scroll="nested-ok"`, `-clip="ok"`.
- `data-ui-audit-overlay` — сама панель, проверками игнорируется.

## Как добавить экран

1. Создать `app/<route>/page.tsx`.
2. Добавить запись в `UI_AUDIT_SCREENS` (тест иначе упадёт). Для модалок — `steps` с `waitFor`/`click` по `data-ui-audit`.
3. Добавить `RouteRule` в `lib/rbac.ts`.

## Плоский стиль — на уровне системы

`tailwind.config.ts` обнуляет шкалы `rounded-*`, `shadow-*` и режет
`duration-*` до ≤100 мс: класс `rounded-2xl` или `shadow-lg` в любом файле
даёт 0 / none. Нарушить голд можно только произвольным значением
(`rounded-[8px]`, `shadow-[…]`) или inline-стилем — прогон это ловит.
Разрешённые произвольные значения: чат Семёна (`OKKConsultantPanel`,
`OKKConsultantAudit`) и спиннеры `rounded-[50%]`. Кольцо Tailwind (`ring-*`,
box-shadow без смещения и размытия) считается границей, не тенью.

## Названия вместо кодов

Клиентский хук `components/useDictionaryNames.ts` (+ `/api/dictionaries`)
резолвит коды RetailCRM в русские имена: `resolve('site', code)`,
`field('typ_customer_margin', value)`, `dictionary('chasovoi_poias', value)`.
Источник — `retailcrm_dictionaries` / `retailcrm_custom_fields`; типы
контрагента заведены миграцией `20260914_contragent_types_dictionary.sql`,
статусы оплаты добавлены в синк. В карточке заказа все справочные поля идут
через него.

## Ограничения

- Прогон гоняется под admin: экраны других ролей выглядят так же по вёрстке, но их фильтрацию по правам не проверяем.
- `covered` при открытом окне не проверяет элементы под ним (они и должны быть закрыты).
- Динамические публичные маршруты (`/invite/[token]` и т.п.) открываются с фиктивным токеном — проверяется экран «ссылка недействительна».
- Штаб (`app/shtab`) живёт на своём CSS с анимациями и тенями — не трогали, остаётся в замечаниях.
- Вложенные прокрутки (`max-h-… overflow-auto` списки внутри страницы) и мелкие зоны касания на телефоне — замечания, не ошибки; чинятся по месту.
