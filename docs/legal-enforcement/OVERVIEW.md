# Исполнительные производства (ФССП) — as-built

> Раздел юридического отдела: `/legal` — реестр (роль `admin`), карточка `/legal/enforcement/{id}`.
> Прежний дашборд юротдела (Дарья + договоры) переехал на `/legal/helpdesk`, ссылка есть в шапке реестра.
> Статус: 🟡 код готов, миграция не применена, в прод не влито. Ветка `feat/legal-enforcement`.

Читать этот файл ПЕРВЫМ, до кода.

## Зачем

Карточку ИП нельзя заполнять руками — 30 полей никто вводить не будет, раздел
умрёт складом PDF. Поэтому: **человек создаёт карточку и грузит документы, бот
заполняет черновик, человек подтверждает спорное.**

## Минимум от человека

| Поле | Кто заполняет |
|---|---|
| Юрлицо группы (должник), ИНН | человек (или бот из документа) |
| Проект (ЗМКТЛ / Столярка / ПО-Консалтинг) | человек |
| Номер ИП | бот, если есть в документе; карточку можно создать без него |
| Документы | человек загружает |
| Взыскатель, суммы, отдел ФССП, пристав, основание, дело суда, лист, период долга, управленческая статья | бот |
| Связанные платежи | бот предлагает, человек подтверждает |

## Поток

```
человек: «+ Новая карточка» → грузит файл (signed upload в бакет legal-enforcement)
   ↓ PATCH /api/legal/enforcement/documents  (файл на месте)
   ↓ parse_status='queued' + job legal_enforcement_parse
крон /api/cron/system-jobs/legal-enforcement-parse (каждые 5 мин)
   ↓ антивирус (мок из контура договоров) → текст (pdf-parse / mammoth / Tesseract OCR)
   ↓ СЫРОЙ текст в legal_enforcement_documents.raw_text  ← без него вывод не доказать
   ↓ regex-слой + ИИ-слой → поля с цитатой и уверенностью
   ↓ legal_enforcement_field_facts (state='suggested')
   ↓ подбор платежей → legal_enforcement_payment_links (state='suggested')
человек: подтверждает / исправляет / отклоняет каждое спорное поле
```

## Доказательство под каждым полем (главное требование)

`legal_enforcement_field_facts`: поле, значение, **цитата из документа**, ссылка на
документ, уверенность, извлекатель (`regex` / `ai` / `human`), конфликт, состояние.
В интерфейсе под каждым предложением видно «Основание в документе: «…»».

Значение попадает в колонку карточки **само** только когда уверенность ≥ 0.75,
поле ещё пустое и другого значения по нему нет. Всё остальное ждёт человека,
карточка стоит в статусе «Нужна проверка».

ИИ обязан вернуть дословную цитату; если цитаты нет в тексте документа — поле
**отбрасывается** (`extract.ts`). Пересказ доказательством не считается. Без
`OPENAI_API_KEY` работает один regex-слой — раздел не падает.

## Статусы карточки

`docs_uploaded → parsed → needs_review → confirmed → payments_linked → in_fd_report → closed`

Статус пересчитывается по фактам (`recalcCaseStatus`), а не по нажатию кнопки.
«Подтверждено» и «Учтено в ФД-отчёте» закрыты, пока есть непроверенные поля.

## Связь с платежами — честное ограничение

`point_payments` хранит **только приход**: и `lib/payments/tbank.ts`, и
`lib/payments/tochka-statement.ts` отбрасывают расход (`Debit`). Списание по
исполнительному производству — расход, и в базе его физически нет.

Подбор (номер ИП / листа / дела в назначении, сумма, ИНН, дата, слова про
приставов; связь предлагается от двух признаков) написан и работает, но до
включения расходов в загрузку выписки почти всегда вернёт пусто. В интерфейсе
об этом стоит явная плашка «в разработке» (ЗАКОН о заглушках).

**Следующий шаг по данным:** включить `Debit` в ingest Точки и Т-Банка (отдельная
работа, трогает прод-конвейер платежей — отдельной веткой и с проверкой, что
приход в `/payments` и в статистике «приход группы» не поехал).

## Что нужно сделать перед прод-запуском

1. Применить `migrations/20260928_legal_enforcement.sql` к базе.
2. Создать приватный бакет Supabase Storage **`legal-enforcement`**.
3. Убедиться, что `CRON_SECRET` на Vercel задан (иначе крон 401 и разбор встанет молча).
4. При желании задать `LEGAL_ENFORCEMENT_MODEL` (по умолчанию `gpt-4o-mini`).

## Как этим пользуется человек

Реестр — плоская таблица, строка = производство. Новая строка заводится прямо в
таблице (юрлицо, ИНН, проект, номер ИП если известен), файлы грузятся **и из
строки реестра, и из карточки**. Клик по строке открывает карточку: поля,
документы, «что нашёл бот» с цитатами, платежи, статус. Кнопка разбора называется
«Расшифровать документы».

Принимаются PDF, Word, txt, сканы-картинки и **архивы ZIP и RAR** — архив бот
раскладывает на отдельные документы карточки и ставит их в очередь разбора
следующим заходом воркера. 7z и tar не читаются: честный отказ с просьбой
пересохранить, потому что пустой результат выглядел бы как пустой архив.

## Грабли

- **Антивирус — мок** (`lib/legal-antivirus.ts`), общий с контуром договоров. Файл с
  «virus» в имени помечается заражённым, остальное считается чистым.
- **PDF без текстового слоя**: `pdf-parse` вернёт пусто, документ получит
  `manual_review_required`. OCR через Tesseract работает для картинок (jpg/png/webp),
  а не для сканов внутри PDF — постановление-скан лучше грузить картинкой.
- **Регулярки заточены под типовые формулировки** ФССП/ФНС (`№ 12345/26/63001-ИП`,
  «взыскатель:», «сумма долга»). Нетиповой документ даст пустой разбор — это видно
  в замечаниях карточки, а не молча.
- **ИНН в документе два** (должник и взыскатель), порядок не гарантирован: оба поля
  идут с низкой уверенностью и всегда уходят человеку на подтверждение.
