# Коннектор Claude к ОКК (MCP)

Как построено и как этим пользоваться. Состояние на 10.11.2026, фаза 1 — только чтение.
Исходное ТЗ писалось под многокомпанийный сервис; здесь компания одна, поэтому
тенантов, `list_companies` и изоляции по `tenant_id` нет.

## Что это

Адрес `https://okk.zmksoft.com/mcp/okk`. Через него Claude читает данные ОКК:
любую таблицу, базы знаний, готовые отчёты и файлы. Записать, отправить или
изменить что-либо коннектор не может.

Подключение в Claude: свой коннектор → адрес выше → вход «Без входа» → заголовок
запроса `X-Api-Key` с личным ключом (годится и `Authorization: Bearer`).

## Инструменты

| Группа | Инструмент | Что делает |
|---|---|---|
| Навигация | `list_sections` | Разделы ОКК, их таблицы и функции |
| | `describe_section` | Таблицы раздела с описаниями, связи, примеры |
| Данные | `search` | Поиск по словам: заказы, клиенты, письма, файлы, дела |
| | `list_entities` | Список строк любой таблицы: фильтры, период, сортировка |
| | `get_entity` | Карточка строки и ссылки на связанное |
| | `get_file` | Текст файла и ссылка на скачивание (15 минут) |
| Базы знаний | `list_knowledge_bases` | Восемь баз с рубриками |
| | `search_knowledge` | Поиск статей по словам |
| | `get_article` | Статья целиком |
| Функции | `list_functions` | Каталог готовых отчётов |
| | `run_function` | Вызов отчёта |
| Аналитика | `schema_lookup` | Таблицы и поля с описаниями |
| | `run_query` | Один произвольный SELECT |

## Почему записать нельзя

1. Весь доступ к данным идёт через функцию базы `shtab_run_readonly_query`
   (общая с Тамарой): транзакция без права записи и таймаут 15 секунд. Запись
   база не выполнит, даже если проверка текста её пропустит.
2. Текст `run_query` проверяется до базы: один SELECT, без цепочек через `;`,
   без записи внутри WITH, без блокировок, без служебных таблиц и чужих схем.
3. `list_entities` и `get_entity` собирают запрос сами: имя таблицы и поля
   сверяются с картой данных, значения уходят экранированными литералами.
4. В каталог функций входит только перечисленное в `READ_ONLY_FUNCTIONS`.
   Всё, что пишет, отправляет сообщения или тратит деньги на ИИ, перечислено в
   `NEVER_VIA_CONNECTOR`, и тест не даёт этим спискам пересечься.
5. С файлами коннектор только выдаёт подписанную ссылку хранилища и читает текст.

## Ключи

```bash
npx tsx --env-file=.env.local scripts/mcp-key.ts issue "Имя Фамилия" почта@учётки
npx tsx --env-file=.env.local scripts/mcp-key.ts list
npx tsx --env-file=.env.local scripts/mcp-key.ts revoke 3
```

- Ключ показывается один раз, в базе лежит только его хеш.
- Отзыв действует сразу: ключ ищется в базе на каждом запросе.
- Уровень доступа один — всё чтение. `mcp_keys.closed_sections` (по умолчанию
  пусто) скрывает от ключа разделы по их коду.
- По решению владельца от 10.11.2026 таблицы с паролями и токенами от коннектора
  не закрыты: утечка ключа коннектора равна утечке всех данных базы.

## Журнал и нагрузка

- Каждый вызов пишется в `mcp_call_log`: кто, инструмент, параметры, число строк,
  время, ошибка. Журнал не чистится.
- Не больше 60 запросов в минуту на ключ. Счётчик живёт в памяти процесса.
- Одновременно в базу от коннектора идёт не больше двух запросов.
- Один ответ — до 50 КБ и до 1000 строк; списки листаются по `next_cursor`.

## Как добавить раздел

Новая таблица видна коннектору сразу — в разделе «Прочее». Чтобы у неё были место
и описание:

1. Строка или правка в `mcp_section`: точное имя в `tables` или начало имени в
   `prefixes`. Код коннектора при этом не меняется.
2. `COMMENT ON TABLE` и `COMMENT ON COLUMN` в миграции раздела — это и есть
   описания, которые видит Claude в `schema_lookup`.
3. Связи без внешнего ключа — в `mcp_section.links`.

Карта данных держится в памяти пять минут, после этого изменения видны.

## Что не сделано

- **Описания полей.** На 10.11.2026 они есть у 245 полей из 2401. Остальные
  Claude видит только по имени.
- **Поиск по смыслу** в базах знаний выключен: каждый запрос — платный вызов
  OpenAI. Сейчас поиск по словам.
- **Отдельная роль базы и отдельный пул соединений** не заведены: запросы идут
  через общий вход Supabase под служебной ролью, запись запрещена транзакцией.
- **Разбор запроса** — по тексту, а не синтаксическим деревом.
- **Вложения писем, ещё не сохранённые в хранилище,** не отдаются: их докачка из
  почты пишет в базу. Сохранённые лежат в `order_files`.
- **Расчёт зарплаты** функцией не вызывается; готовые расчёты читаются из
  `salary_calc`.
- **Выдача ключей** — только скриптом, экрана в настройках нет.
- **Фаза 2 (запись)** не начата.

## Известное

- Функция `sales_facts` падает с ошибкой базы `invalid input syntax for type json`
  (`sales_month_facts` читает код статуса как JSON). Это не коннектор: так же она
  падает и у Тамары.
- `shtab_run_readonly_query` превращает строку в JSON записью `to_jsonb(t)`; при
  колонке с именем `t` в запросе возвращается она, а не строка. Коннектор обходит
  это упаковкой строки в одну колонку (`lib/mcp/sql.ts`), у Тамары обхода нет.
