# Претензионно-исковая работа — as-built

> Раздел юротдела: реестр дел `/legal/matters`, карточка дела `/legal/matters/{id}`.
> Статус: 🔴 проектируется, кода нет. Ветка `feat/legal-matters`.

Читать этот файл ПЕРВЫМ, до кода.

## Зачем

Сейчас один спор распадается на несвязанные карточки: суды живут в
`court_cases`, исполнительные производства — в `legal_enforcement_cases`,
связь между ними только текстом в `court_case_number`. Досудебной стадии —
претензии, переговоры — нет вообще, а это самый массовый этап работы юриста.

Руководителю нужен не список дел, а ответ на вопрос «что происходит по каждому
спору, кто отвечает, сколько денег на кону и какое следующее действие».

## Решения (Андрей, 28.09.2026)

| Вопрос | Решение |
|---|---|
| Что считается одним делом | **Один конфликт.** Не договор и не контрагент: три поставки одному покупателю в рамках одного спора — одно дело |
| Кто заводит дело | **Только юрист.** Менеджер/РОП дело не создаёт |
| Наши претензии к контрагентам | **В том же реестре**, что и претензии к нам (дебиторка — наша претензия) |
| Юрлица группы | По ИНН: ЗМК, ЗВТО, ПОБТ, ИП Теренков, Теренков Инвестиции |
| Денежный блок | **Полный**: требование, неустойка, убытки, госпошлина, судебные расходы, взыскано, выплачено |

## Принципы

1. **Один конфликт = один постоянный ID.** Претензия → переговоры → иск → суд →
   апелляция → исполнительное производство — стадии одного дела, не новые строки.
   ID не меняется никогда.
2. **Последнее действие не вводится руками** — вычисляется из журнала событий.
   Иначе реестр разъезжается с историей (главная болезнь Excel-варианта).
3. **Следующее действие + срок — обязательны.** Из них строятся задачи юриста и
   экран руководителя. Пустого «следующего шага» у активного дела быть не может.
4. **Человек создаёт дело и грузит документы, бот заполняет черновик полей
   с дословной цитатой, человек подтверждает спорное.** Механизм переиспользуется
   из `lib/legal-enforcement/` (`extract.ts`, `facts.ts`) — не писать заново.
   Пересказ доказательством не считается: нет цитаты — поле отбрасывается.
5. **Любое число раскладывается до слагаемых.** «Финансовый риск» на экране
   руководителя раскрывается до требования, неустойки, расходов и урегулированной
   части по клику.
6. **Мало статусов.** Потолок — 7.

## Чего нет ни у нас, ни в исходном предложении

- **Срок исковой давности** — пропуск означает потерю денег безвозвратно.
  Нужны дата возникновения права требования, дата истечения ИД, предупреждение заранее.
- **Связь с заказом и договором в CRM** — иначе двойной ввод контрагента и сумм.
- **Госпошлина** отдельно от судебных расходов: платится вперёд, возвращается отдельно.
- **Представитель контрагента** — на переговорной стадии нужнее, чем судья.
