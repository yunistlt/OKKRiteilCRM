# Фото товаров — через российский сервер ОКК

## Что произошло

Сайт `zmktlt.ru` отвечает только российским адресам. Проверка 06.10.2026:

| Откуда | Картинка `.../49166.750x0.jpg` |
|---|---|
| зарубежный адрес | соединения нет вовсе |
| российский сервер | HTTP 200, 20 797 байт, `image/jpeg` |

Приложение ОКК работает на Vercel (Франкфурт), поэтому:

* в карточке заказа фото товара не грузилось;
* **в КП клиенту уходила пустая колонка «Фото»** — молча, без ошибки: сборщик
  PDF просто пропускает картинку, которую не смог забрать (проверено сборкой
  КП с недоступным адресом — файл собрался, фото исчезло).

## Где это чинится

У ОКК **свой** российский сервер — `OKKRiteil` в Timeweb (ru-3, 201.24.121.53).
Домен `okk.zmksoft.com` смотрит на него, там стоит nginx, который проксирует
запросы в Vercel (`server: nginx/1.24.0`, ответ с `x-vercel-id`).

Картинки отдаём через него же, с того же домена. Сервер ЦехУспеха (`zeh2`,
`erp.zmksoft.ru`) к ОКК отношения не имеет и для этого не используется.

## Что сделать на сервере OKKRiteil

1. Бэкап конфига nginx.
2. В секцию `server` домена `okk.zmksoft.com` добавить **до** общего
   `location /`:

```nginx
    # Фото товаров сайта zmktlt.ru: сайт пускает только российские адреса, а
    # приложение ОКК работает на Vercel во Франкфурте — картинки до него не
    # доходили (разбор 06.10.2026). Этот сервер стоит в России и ходит за
    # картинкой сам.
    #
    # Пропускаем ТОЛЬКО /wa-data — папку медиафайлов магазина. Открытого
    # прокси не делаем: иначе через нас можно было бы ходить куда угодно.
    location /wa-data/ {
        proxy_pass https://www.zmktlt.ru;
        proxy_set_header Host www.zmktlt.ru;
        proxy_ssl_server_name on;
        add_header Cache-Control "public, max-age=86400";
    }
```

3. Применить: `nginx -t && systemctl reload nginx`
4. Проверить:

```
curl -o /dev/null -w "%{http_code} %{size_download} %{content_type}\n" \
  https://okk.zmksoft.com/wa-data/public/shop/products/61/85/28561/images/49166/49166.750x0.jpg
```

Ожидается `200 20797 image/jpeg`.

## Что сделать в Vercel

Добавить переменную окружения и передеплоить:

```
CATALOG_IMAGE_PROXY_BASE=https://okk.zmksoft.com
```

До этого момента ОКК работает как раньше — подмены нет.

## Код

`lib/own-crm/catalog-image.ts` — подмена адреса. Подменяются только медиафайлы
(`/wa-data/`) и только у хостов `zmktlt.ru` / `www.zmktlt.ru`; переменная не
задана — адрес остаётся прежним, и в России всё работает напрямую, как раньше.

## Проверено 06.10.2026

Прокси включён, фото отдаётся с нашего домена с зарубежного адреса:

```
https://okk.zmksoft.com/wa-data/.../49166.750x0.jpg → 200, 20 797 байт, image/jpeg
```

**Грабли:** бэкап конфига нельзя класть в саму папку `sites-enabled` — nginx
подхватывает оттуда ВСЕ файлы, и копия начинает спорить с живым конфигом
(`conflicting server name "okk.zmksoft.com"`). Копию держать в `/root/` или
`/etc/nginx/backups/`.

## Открытый вопрос по доступу

В `~/.ssh/config` хост `okk` указывает на `5.42.126.228`, а у сервера
`OKKRiteil` адреса `5.42.111.117` и `201.24.121.53`. При подключении к
`5.42.126.228` ssh сообщает, что **ключ хоста изменился** — похоже, адрес
освободили и отдали другому клиенту. Подключаться к нему нельзя: запись в
`~/.ssh/config` нужно поправить на настоящий адрес сервера, а старый ключ
убрать из `~/.ssh/known_hosts` (строка 3).
