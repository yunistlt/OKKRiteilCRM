## Как выкатить новую сборку

```bash
npm run build
cd .next/standalone && cp -R ../static .next/static && cp -R ../../public . && cp ../../vercel.json .
COPYFILE_DISABLE=1 tar --no-xattrs --exclude='._*' -czf /tmp/okk-<sha>.tar.gz .
scp -i ~/.ssh/cexuspeh_vps /tmp/okk-<sha>.tar.gz root@5.42.111.117:/opt/okk/releases/
ssh -i ~/.ssh/cexuspeh_vps root@5.42.111.117 '/opt/okk/deploy.sh /opt/okk/releases/okk-<sha>.tar.gz'
```

Сборку делаем на своей машине: на 4 ГБ рядом с работающим приложением собирать
нечем. `deploy.sh` сам проверяет, что новый выпуск отвечает, и возвращает
прежний, если нет. Чистит только свои каталоги `okk-*` — рядом живёт чужой стенд.

## Грабля, на которую наступили

**Редиректы вели на `localhost:3000`.** В своей сборке (standalone) Next кладёт
в `request.url` не внешний адрес, а `localhost:<порт>` — и `middleware.ts`
отправлял браузер на вход по адресу `https://localhost:3000/login`, то есть в
никуда. На Vercel не видно: там `request.url` настоящий. Лечение — `publicUrl()`
в `middleware.ts`: адрес берём из заголовков nginx. В `okk-prodtest.conf`
`Host` — это `$http_host`, а не `$host`, иначе теряется порт и проверочный
адрес выкидывает на боевой.

Там же рядом: ссылки в письмах и КП и вебхук Точки берут адрес из
`NEXT_PUBLIC_APP_URL` — он прописан в `/etc/okk.env`.

## Что осталось до переключения людей

1. **Этап 2 — проверка руками по списку из плана.** Нужен человек с учётками:
   вход в трёх ролях, заказы, карточка, письма, звонки, мессенджер, Елена,
   Семён, зарплата. Автоматом проверено только то, что ниже.
2. **Два секрета.** `JWT_SECRET` и `CRON_SECRET` в `.env.local` отсутствуют, с
   Vercel их не достать (нет cli и токена) — сгенерированы новые. У кода есть
   запасное значение, поэтому вход работает, но **в момент переключения все
   текущие сессии станут недействительны: люди войдут заново один раз.** Если
   этого не хочется — взять настоящий `JWT_SECRET` из переменных Vercel и
   положить в `/etc/okk.env` до переключения.
3. **Переменные могут отставать.** `/etc/okk.env` собран из `.env.local`, а он
   уже расходился с Vercel (заметка про «Access denied» у Тамары). Сверить с
   панелью Vercel.
4. **Этап 3 — переключение.** `proxy_pass` на `http://127.0.0.1:3000` в
   `okk.zmksoft.com`, `nginx -t && systemctl reload nginx`. Кроны: сперва убрать
   `crons` из `vercel.json` и выкатить на Vercel, и только потом
   `mv /etc/cron.d/okk.disabled /etc/cron.d/okk`. Иначе задачи пойдут дважды.
5. **Сторож.** В `ops/watchdog` добавить проверку `okk.service`.

Откат на любом шаге: `proxy_pass` обратно на Vercel + `reload`. Деплой на Vercel
не удалять неделю.
