# Переезд на свой сервер: на чём встали 25.10.2026

Попытка перевести ОКК с Vercel на свой сервер Timeweb откачена в тот же день.
Приложение на сервере работает, людей не переключали, ничего не потеряно.
Здесь — почему встали и что нужно, чтобы довести.

## Главный упор: Vercel не отдаёт секреты

Переменных в production — 49. Значения **17 из них получить невозможно**:
Vercel помечает их `Sensitive`, и после сохранения их не показывает никому —
ни в панели (замок вместо глаза), ни по API, ни своей же программой
(`vercel env pull` пишет `Secret values cannot be pulled`).

Что удалось собрать: 32 переменные — из `.env.local` владельца и из тех, что
Vercel отдаёт открыто (ключи Телфина, каталог, Webasyst, LVZ).

### Чего не хватает и что из-за этого не работает

| Переменные | Что молчит без них |
|---|---|
| `TOCHKA_JWT_TOKEN`, `TOCHKA_WEBHOOK_JWKS_URL` | приём оплат от Точки |
| `TBANK_API_TOKEN`, `TBANK_API_BASE` | выписка Т-Банка |
| `TELEGRAM_PAYMENTS_BOT_TOKEN`, `TELEGRAM_PAYMENTS_CHAT_ID`, `TELEGRAM_PAYMENTS_ROUTES`, `TELEGRAM_PROJECT_STOLYARKA_CHAT`, `TELEGRAM_PROJECT_CONSULTING_CHAT`, `TELEGRAM_WEBHOOK_SECRET` | уведомления об оплатах и по проектам |
| `VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT` | push в мессенджере |
| `STT_URL`, `STT_WORKER_TOKEN`, `STT_PULL_MODE` | транскрибация звонков |
| `TSEH_API_URL`, `TSEH_API_KEY` | передача заказов в ЦехУспех |
| `YANDEX_DIRECT_TOKEN`, `YANDEX_WEBMASTER_TOKEN` | Тамара: Директ и Вебмастер |

Часть восстанавливается без владельца: настройки обратного звонка Телфина
(очередь 200, добавочный 105 — есть в заметках), адрес нашего STT-сервера
(смотрится на самом сервере `okk-stt`), пара VAPID (генерируется заново, но
тогда push-подписки слетают и люди переподписываются при открытии мессенджера).
Остальное — только из кабинетов: Точка, Т-Банк, BotFather, ЦехУспех, Яндекс.

**Вывод: до переезда нужно собрать эти значения в одном месте.** И держать их
не только в Vercel — иначе мы заложники чужой панели.

## Что я сделал не так (мои ошибки)

1. **Слияние веток вернуло кроны в `vercel.json`.** Разрешая конфликт, взял
   файл из `main` целиком — и 52 крона вернулись в файл, который я же перед
   этим от них очистил. Первая выкатка ушла с кронами. Поймал проверкой через
   API, исправил отдельным коммитом. Урок: после разрешения конфликта смотреть
   diff того файла, из-за которого конфликт и был.
2. **Залил на сервер файл настроек с пустыми значениями.** Выгрузка из API
   Vercel вернула 43 переменные пустыми (это и были секреты), а я записал их
   как есть и перезапустил службу — в том числе с пустым `DATABASE_URL`.
   Заметил по тому, что крон стал отвечать 401, вернул из резервной копии.
   Урок: перед заменой боевого файла настроек считать пустые значения и не
   применять, если их больше нуля.
3. **Сначала переносил, потом сверял.** Сверку переменных надо было делать
   первым шагом, а не после того, как приложение уже стояло на сервере.

## План, когда вернёмся

1. Собрать 17 недостающих значений (кабинеты сервисов) в один файл.
2. Положить их на сервер, перезапустить службу, сверить: пустых значений — ноль.
3. Прогнать по списку: звонки, письма, оплаты, Telegram, push, транскрибация,
   ЦехУспех, зарплата, Елена, Семён.
4. Выключить кроны на Vercel → включить на сервере → сутки смотреть.
5. Переключить nginx, неделю держать Vercel как откат.

Пункт 1 — не техническая работа, а сбор доступов. Пока он не сделан, переезд
трогать не стоит.
